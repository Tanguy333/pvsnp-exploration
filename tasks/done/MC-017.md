## Ce qui a été fait

Script : `checks/mc017_totalisation.py` (solveur PARTIEL — contraintes
U × B seules — + total + complétions exhaustives + MUX). Mesures :
`data/mc017_totalisation.md`. 9 instances, ~90 résolutions OPTIMAL,
0 non-conclu, < 10 s.

1. **Q0** : min-complétions = W_partiel sur 3/3 instances exhaustives
   (s = 3, 16-32 complétions chacune) — et l'optimum est RARE (1/32,
   6/32, 9/16) : les complétions canoniques (∗→0, ∗→1) le ratent
   jusqu'à un facteur 2,5.
2. **Q2** : la totalisation MUX minimale — h(1,·) = f₀, h(0,·) = 𝟙_∗ —
   mesurée sur les 9 instances : δ = W(MUX) − (W(f₀) + W(𝟙_∗) + 1)
   ∈ {−1 : 2, 0 : 6, +2 : 1}. Les δ = −1 confirment par l'exemple que
   le plancher du sélecteur (MC-006) ne vaut qu'en blocs DISJOINTS.
3. **Correction en cours de tâche, marquée** : la première impression
   du script étiquetait la référence somme+1 « plancher MC-006 » — faux
   en espace partagé ; étiquette corrigée AVANT consignation, valeurs
   inchangées au replay (consigné dans le fichier de mesures).
4. Verrou requalifié et cible suivante nommée (MC-018 candidate) :
   Q0 à plus grande échelle + mécanismes de couplage à sélection
   multi-bits (la zone entre le MUX 1 bit et les O(log) blocs
   disjoints).

# A-006 : Audit — Baker, Gill & Solovay 1975 (relativisation)

> Tâche type A. Exécutée le 2026-06-09.
> **Sourçage** : original SIAM paywallé. Audit fondé sur les notes de cours de
> J. Katz (UMD, 2008, [PDF](https://www.cs.umd.edu/~jkatz/complexity/f05/relativization.pdf),

## 1. Référence canonique

- T. Baker, J. Gill, R. Solovay, *« Relativizations of the P =? NP
  Question »*, SIAM Journal on Computing, vol. 4, no. 4, 1975, pp. 431-442.
  [doi:10.1137/0204037](https://doi.org/10.1137/0204037).
- Contexte ultérieur souvent cité avec : Bennett-Gill 1981 (relativement à un
  oracle *aléatoire*, P^A ≠ NP^A avec probabilité 1, SIAM JC 10:96-113).

## 2. Théorème principal — énoncé et constructions exactes

> « The main result […] is to show the existence of oracles A, B such that
> P^A = NP^A while P^B ≠ NP^B. A fancy way of expressing this is to say that
> the P vs. NP question has contradictory relativizations. »

### Oracle A (effondrement) — une ligne

> « Let A be a PSPACE-complete language. It is obvious that P^A ⊆ NP^A for
> any A, so it remains to show that NP^A ⊆ P^A. We do this by showing that
> NP^A ⊆ PSPACE ⊆ P^A. »

(Le non-déterminisme + les requêtes à A se simulent en PSPACE ; PSPACE se
Cook-réduit à A.)

### Oracle B (séparation) — diagonalisation paresseuse

Langage témoin : `L_B = {1ⁿ : B ∩ {0,1}ⁿ ≠ ∅}` — toujours dans NP^B
(deviner x, interroger l'oracle).

Construction par étapes contre une énumération M₁, M₂, … des machines
déterministes poly-time (temps p_i) :

> « Let n_i be the smallest integer such that 2^{n_i} > p_i(n_i) and also
> n_i > p_j(n_j) for all 1 ≤ j < i. Run M_i(1^{n_i}) and respond to its
> queries according to B_{i−1}. Let Q = {q₁, …} be the queries of length
> exactly n_i that were made by M_i, and let x ∈ {0,1}^{n_i} ∖ Q […] If
> b = 0 then set B_i = B_{i−1} ∪ {x}; if b = 1 then set B_i = B_{i−1}. »

**Le fait structurel unique** : une machine poly-time ne peut pas interroger
les 2ⁿ chaînes de longueur n — il reste toujours un x non-vu où cacher (ou
ne pas cacher) le témoin. M_i se trompe sur 1^{n_i}, et les étapes
ultérieures ne perturbent pas les précédentes (longueurs croissantes).

## 3. Hypothèses non-triviales

1. Énumérabilité des machines poly-time avec horloges (standard).
2. **C'est tout.** La preuve est élémentaire — sa force est conceptuelle,
   pas technique : elle montre que tout argument *insensible à l'ajout d'un
   oracle* ne peut trancher P vs NP, puisque la réponse dépend de l'oracle.

## 4. Outils techniques

- Diagonalisation paresseuse (lazy oracle construction).
- Simulation PSPACE du non-déterminisme avec oracle.

## 5. Ce que le papier NE PROUVE PAS

1. **Pas que P vs NP est insoluble** — seulement que les techniques qui
   relativisent (simulation, diagonalisation pure, padding) ne suffisent
   pas. Katz, verbatim :
   > « It is important to note, however, that various non-relativizing proof
   > techniques are known; as one example, the proof that PSPACE ⊆ IP does
   > not relativize (it is known that there exists an oracle A such that
   > PSPACE^A ≠ IP^A). »
2. **Pas de définition formelle de « preuve qui relativise »** — la notion
   est opérationnelle, pas mathématiquement délimitée (débat classique :
   Hartmanis et al., *Relativization: A Revisionist Retrospective*, 1993 ;
   Fortnow 1994 — cités dans les notes).
3. **L'oracle aléatoire ne tranche rien** : Bennett-Gill 1981 donnent
   P ≠ NP relativement à un oracle aléatoire avec probabilité 1, mais la
   « random oracle hypothesis » est fausse en général (IP = PSPACE échoue
   relativement à un oracle aléatoire).

## 6. Statut de barrière (lecture pour l'Atlas)

Barrière #1 du cahier (§1). Test opérationnel issu de l'audit :

> Si un argument traite la machine/le vérificateur comme une **boîte noire**
> (il resterait valide si on ajoutait un oracle arbitraire aux deux classes),
> alors il ne peut pas prouver P ≠ NP (l'oracle A le contredirait) ni
> P = NP (l'oracle B le contredirait).

Le « certificat moderne » d'évitement est celui de Williams (audit A-001) :
exhiber un oracle relativement auquel l'énoncé visé est *faux* (pour NEXP
vs ACC : NEXP^A ⊂ ACC^A, Aaronson) — alors toute preuve de l'énoncé est
nécessairement non-relativisante.
